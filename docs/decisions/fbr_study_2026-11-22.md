# Secondary study: finding-balanced recovery (FBR) (2026-11-22)

**Status:** decided 2026-11-22 (research lead); recorded and committed 2026-11-23, before any FBR
code was written or run. Pre-registration section 10, amendment of 2026-11-22.
**Scope:** **exploratory**, outside H1-H4: no verdicts, no multiplicity correction, no change to a
pre-registered metric, to the comparator (E5 magnitude) or to the futility outcome. Developed
after the futility stop, from seed-0 **validation** results. PolypGen checks the polyp endpoints
only, so any claim about the rare findings (oesophagitis, ulcerative colitis) rests on the
internal test alone.

## 1. What informed it (validation, seed 0, B2)

- Gate 2 (`docs/results/GATE2.md`): the comparator is E5 magnitude; E7 ranks below it; the
  futility rule stopped the main tier after seed 0.
- The plain-answer collapse (GATE2.md): the plain answers (margin threshold 0) of E5 magnitude,
  E5 activation and E6 say "no" to every mask-positive polyp probe; their plain macro balanced
  accuracy is 0.500, E7's 0.688. These are the **collapsed arms** named below.
- E5R's oesophagitis drop: operating-point sensitivity 0.89 to 0.24, AUROC 0.961 to 0.880 (E2 to
  E5R, validation). E2's values are in its committed validation rows
  (`results/E2/nobudget/seed0/metrics.csv`: `op_sensitivity:oesophagitis` 0.892, 33 of 37;
  `auroc:oesophagitis` 0.961). E5R's are **as reported by the research lead**: E5R's stage 06 is
  not committed.

**What did not inform it.** No test-split or PolypGen result. The seed-0 B2 test evaluations of
E5 (three criteria) and E6 were committed on 2026-11-23, before this record, by SHA-256, file
list and row counts only; no value in them was opened. No E7 test result exists yet (RC-E7 is
running).

## 2. Diagnostic (CPU over saved arrays; validation only)

For each B2 pruning arm with its arrays (E5 magnitude / activation / Taylor, E5R, E6, E7, E7U) and
for E2, per finding (polyp, oesophagitis, ulcerative colitis):

- the margin m = log p(yes) - log p(no) at the answer position (the evaluation's
  `probe_margin`; section 4 defines it) by label: count, quantiles (5, 25, 50, 75, 95 %);
- the rank of the yes and no tokens against the whole vocabulary at the answer position (best
  rank over each answer's spellings; 1 = the top token);
- agreement between the margin's sign and the decoded free answer; parse failures;
- AUROC and average precision of the margin.

**Recalibration**, each fitted with the cross-fitting of section 6 (fit on two folds, apply to
the third):

- intercept per finding: p = sigmoid(m + b_f), b_f minimising the summed negative log-likelihood
  of the fitting folds plus b_f^2 / 2 (ridge, weight 1);
- one pooled temperature: p = sigmoid(m / T), T > 0 minimising the summed negative
  log-likelihood of the fitting folds over all findings.

Reported for the raw margin and both fits: Brier, balanced accuracy at the fixed cutoff p = 0.5,
AUROC, and the cross-fitted sensitivity at specificity >= 0.95 (section 6). Everything is counted
by image (one probe per image and finding), never by paraphrase.

**Data the diagnostic needs that the evaluation does not save:** the decoded free answer to each
probe and the token ranks. A GPU pass writes them per arm (`probe_answers_val.npz`, section 9,
cell (i)); until a file exists the diagnostic prints "not available" for those columns. The
diagnostic refuses any split other than validation.

## 3. The recipe (identical for every arm)

**Start.** Each arm's pruned model **before recovery**, rebuilt from E2 seed 0 (merged) and the
arm's committed `removal.json`, with the pruning code that made it. Checked before training: the
parameter count equals the arm's committed `parameters_after` (stage 05), the removal set and
the per-layer counts equal `removal.json` and `removal_by_layer.csv`.

**Unchanged from the registered recovery** (`configs/recovery.yaml`): LoRA rank 16, alpha 32,
dropout 0.05 on the same modules; AdamW, learning rate 1e-4, linear schedule, 20 warm-up updates,
gradient-norm clip 1.0; 157 updates of effective batch 16 (micro-batch 1 x 16 accumulation); fp16
autocast with the same dynamic loss scaling; the vision tower frozen; the same prompt and answer
formatting; non-finite updates skipped by the loss scaler and logged as the registered recovery
logs them; the model after the last (157th) update is the result (no checkpoint selection). FBR
reads these values from the registered recovery section; a test checks the shared keys are equal.

**Each effective batch of 16:**

- 10 ordinary examples from the registered recovery pool, in the registered seeded order (seed 0,
  the same `select_subset` order), consumed 10 per update: update t uses positions 10t to 10t+9.
  157 x 10 = **1,570 ordinary examples** (the registered recovery sees 157 x 16 = 2,512).
  Their loss is the **registered per-example loss**: L0 = (1 - w) CE + w KL(T), w = 0.5, T = 2,
  KL on the cached 7B top-20 logits (`_step_backward`). (The request wrote "CE + 0.5 KL"; the
  registered code, which "unchanged" refers to, weights CE by 0.5 too. The registered form is
  locked.)
- 6 labelled training probes: one positive and one negative for each of polyp, oesophagitis and
  ulcerative colitis.

**Probe rules.** Training split only; the evaluation's probe template and display names
(`build_probes`); a negative only where the label says the finding is absent (an image without a
label for a finding gives no probe for it); per (finding, label) stratum, the unique images in a
deterministic shuffle (seed 0) are used once each before any repeats, then reshuffled (seed 0
plus the cycle number); unique images and reuse counts per stratum are logged. The schedule
(which probe at which update) is computed before training and saved; it does not depend on the
model.

**Probe loss.** Per probe: teacher-forced cross-entropy over the full vocabulary on the correct
answer with the registered answer formatting (the answer text, then the end token). Per finding f
and update, the paired margin difference d_f = m(x+) - m(x-) for the student, and d_f(E2) for E2
seed 0 (cached once, offline, on one T4, for every probe of the schedule; section 9, cell (ii)).
Margins and their reductions in fp32.

**Total loss of an update:**

L = (10/16) mean_general(L0) + (6/16) [ mean_probe(CE) + 0.25 mean_f Huber_1(d_f - d_f(E2)) ],

Huber with delta 1. **The coefficients 10/16, 6/16, 0.25 and delta 1 are fixed and are not
tuned.** With micro-batch 1 and accumulation 16, each ordinary micro-batch contributes L0 / 16 and
each probe micro-batch CE / 16, which is the formula above. The paired term needs both members'
margins: each probe's margin gradient over the trainable (LoRA) parameters is taken from its own
forward pass under the same loss scale, kept, and the term's gradient
0.25 (6/16) (1/3) Huber'(r_f) (grad m(x+) - grad m(x-)), r_f = d_f - d_f(E2), is added once both
members are done. It is the exact gradient of L with one graph alive at a time (a test compares
it with a joint graph). A non-finite margin or gradient makes the whole update non-finite: the
loss scaler skips it, as any other.

**Control "sampling-only":** the same recipe with the coefficient 0.25 set to 0 (so the probe
term is plain cross-entropy on the probes).

## 4. The margin and the answer token

m is the evaluation's margin: log of the summed probability of the single-token spellings of
"yes" minus that of "no" (`YES_SPELLINGS`, `NO_SPELLINGS` in `models/tokens.py`: case and leading
space variants), at the first answer position, i.e. logsumexp of the logits over the yes ids minus
logsumexp over the no ids. With one spelling per answer it is z(yes) - z(no). The student, E2's
cache and every diagnostic use the same function; a test checks that the teacher-forced first
answer slot of the training forward pass gives the same margin as the evaluation's scoring path
on the same probe.

The cross-entropy target spelling is fixed before training (cell (ii)): the single-token spelling
that E2 decodes most often as its first answer token on the schedule's probes, separately for
"yes" and for "no", reported with the token ids and decoded examples. If the spellings E2 decodes
are not single tokens of the yes / no sets, the study stops and the research lead is told.

## 5. Pilot (B2, seed 0, validation only)

FBR on E5 magnitude, E5 activation and E7, and the sampling-only control on E5 activation; each
compared with its arm's registered recovery (the committed B2 run). Evaluation of each new model:
the standard validation pass (all suites, `outcomes.npz`) and the probe-answer pass of cell (i).

## 6. Operating points (cross-fitted)

Folds: images grouped (all probes of an image in one fold), stratified by the image's
finding-presence stratum (as the re-calibration draws of 2026-11-20), assigned deterministically
(seed 0), **identical across arms** (they depend on the validation labels only). Three folds when
every fold holds at least **5 positive and 5 negative images of every finding**; otherwise two
folds; decided from the label counts alone, before any model output is read. A finding without
5 and 5 in every fold of two folds gets no cross-fitted operating point (reported as such).

The threshold for specificity >= 0.95 (the pre-registered rule, `fit_thresholds`) is fitted on
the other folds and applied to the held-out fold; the held-out decisions of all folds are pooled
and the achieved specificity is reported. **Every operating-point quantity in the gate uses these
cross-fitted decisions.**

## 7. Gate (absolute percentage points, each arm against its own registered recovery)

- R = mean of the oesophagitis and ulcerative-colitis cross-fitted sensitivities: **delta R >= 5**;
- neither rare sensitivity drops by more than 3;
- neither rare cross-fitted specificity drops by more than 2;
- decoded free-answer macro balanced accuracy (section 8): **+3 or more** on the collapsed arms
  (E5 magnitude, E5 activation), **no more than -2** on the others (E7);
- macro Brier (p = sigmoid(m)) worsens by at most 0.01;
- polyp cross-fitted operating-point recall drops by at most 3.

**Pass** = E5 magnitude and E5 activation both pass every item. E7 is reported either way. If
sampling-only is indistinguishable from FBR on E5 activation (the paired bootstrap 95 % interval
of FBR minus sampling-only on delta R contains 0), the effect is credited to the simpler control.
A failed gate is a result: no coefficient, recipe or threshold is searched.

## 8. Definitions and report

- **Decoded free answer:** greedy decoding of the probe question, at most 8 new tokens; the text
  is lower-cased and stripped, its first word stripped of punctuation; "yes" is a yes, "no" a no,
  anything else a parse failure. A parse failure counts as wrong for both positives and
  negatives. The margin-sign (plain answer) version of the same balanced accuracy is reported
  beside it.
- **Probability** for Brier, NLL and ECE: p(yes) = sigmoid(m) (renormalised over the two
  answers); ECE on the confidence max(p, 1 - p) with the pre-registered 15 equal-width bins.
- **Report:** per-finding counts with denominators; confusion matrices at the native threshold
  (m = 0) and at the cross-fitted operating point; AUROC, AP, NLL, Brier, ECE; image-cluster paired
  bootstrap 95 % intervals (10,000 resamples, seed 0) with the cross-fitted thresholds refitted
  inside each resample; the lesion-mask audit in both versions (plain answer and operating
  threshold) and the paired change of the continuous margins (original, lesion masked, random
  masked).

## 12. Clarification of 2026-11-24 (research lead), before any FBR training run

**What happened.** Cell (ii) stopped as designed (section 4's rule): on the schedule's 942
training probes, E2 seed 0's greedy first answer token was "No" (token 2753) 307 times, another
token 635 times and a yes spelling never ("yes {}, no {2753: 307}, other 635", from the cell's
log as reported by the research lead). No FBR training has run.

**A finding about the parent model (E2).** E2 does not answer a probe with a leading "yes": it
answers "No" or starts with another token (the diagnosis printed by cell (ii) from now on lists
the 20 most frequent other first tokens, decoded, and 10 decoded answers each to positive and
negative probes, read by the pre-registered parser). How the evaluation reads such answers:

- the **plain answer** (the probe metrics' yes/no) parses no text: it is the sign of the pooled
  margin at the first answer position, logsumexp of the logits over every single-token yes
  spelling minus over every no spelling (`HFVLMWrapper.yes_no_logprobs`). It has no "unparsed"
  state. When most of the first token's probability goes to other tokens, the margin compares two
  small probabilities, and E2 puts more of it on "No" than on any yes spelling even on positives;
- this explains E2's low plain-answer metrics on validation (committed rows: macro balanced
  accuracy 0.553; mask-audit original yes-rate 0.209; plain yes-rates 0.106, 0.013 and 0.009 for
  polyp, ulcerative colitis and oesophagitis) next to its high ranking quality (AUROC up to
  0.961): the information is in the margin's order, the threshold 0 is off. The pre-registered
  operating point (a per-finding threshold at specificity 0.95) reads the order and is not
  affected;
- the **pre-registered text parser** (`clinical.parse_yes_no`, pre-registration section 6:
  lower-cased, leading non-letters dropped, the answer must start with the word "yes" or "no")
  is not used by the probe metrics. Applied to E2's decoded answers it returns "no" for the
  answers that start with "No" and "unparsed" for those that start otherwise: on the schedule's
  training probes at most 307 of 942 parse (all as "no") and at least 635 (67 %) are unparsed,
  by the first-token counts above (cell (ii) now counts it exactly on the decoded answers).

**Changes (they fix the readout, not the recipe; coefficients, batch, gate items unchanged):**

1. **Margin.** m is exactly the evaluation's pooled margin (section 4), for the student, E2's
   cache and every diagnostic. No token is "chosen" for it: the empirical choice of section 4
   (the spelling E2 ranks first most often) and its stop are removed.
2. **Cross-entropy target.** The canonical answer strings of the probe template,
   `domain.probe.answers` in `configs/domain/endoscopy.yaml`: **"yes"** for a positive and
   **"no"** for a negative (lower case, the reference answers `build_probes` stores), each with
   the registered formatting (the answer, then the stop token). Each must encode to exactly one
   token, and that token must be one of the evaluation's single-token yes (no) spellings; if
   not, the study stops and the research lead is told (the check and its stop stay).
3. **Decoded free answer.** Parsed by the pre-registered parser `clinical.parse_yes_no` (the
   same rule as section 8 in substance, one implementation for FBR and the evaluation);
   unparsed counts as wrong for positives and negatives, as before.
4. **Reading the gate (a confound).** FBR trains the probe answers' format (a direct "yes" /
   "no"), so it can raise the plain-answer and decoded free-answer metrics through the format
   alone, without any change in what the model knows. The **primary gate quantity stays the
   cross-fitted rare-finding sensitivity** (R and its items): it uses per-finding thresholds on
   the margin's order, so a format change that moves a finding's margins together leaves it
   unchanged. A change in the plain-answer or decoded free-answer metrics is reported as a
   **format and readout result**, not as restored knowledge; the decoded-answer gate item is
   read the same way.

**Checked for the same assumption (2026-11-24):** the evaluation's scorer reads only the first
answer position (pooled over the single-token spellings; frozen, unchanged; its reading is the
one above); `fbr_probe_answers.py` takes the token ranks at the same position (best rank over
each answer's spellings) and decodes up to 8 tokens before parsing, so it records what E2 says
rather than assuming a yes/no first token; E2's margin cache no longer stops on the first token.

## 13. Note of 2026-11-25: E2 answers in the dataset's style

Cell (ii) passed the single-token check (targets "yes" 9693, "no" 2152) and showed that E2 never
starts an answer with a yes spelling: first token "e" ("evidence of ...") or "No" ("No evidence
of ..."). The CE targets therefore teach a format E2 never uses: any change in the pre-registered
plain readout, or in the decoded-answer gate item read with the pre-registered parser, after FBR
is a format effect; the native-format readout (`docs/decisions/native_readout_2026-11-25.md`) is
the relevant plain check, reported beside the locked item and not used for the verdict. The
primary gate quantity is unaffected. Four schedule probes have a non-finite E2 margin (labels not
recorded): at most 4 of the 157 updates are skipped (rule of 2026-11-25). The recipe is unchanged.
